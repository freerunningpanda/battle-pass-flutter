# Battle Pass — тестовое задание · Flutter

Главный экран боевого пропуска (БП) по [макету в Figma](https://www.figma.com/design/cCWtK0v3plrmwvPO9DZCRU/) —
три обязательных состояния, мок-данные, `flutter_bloc` (Cubit), лёгкая Clean Architecture.

## Как запустить

```bash
flutter pub get
flutter run
flutter test
```

Ограничений по окружению/`--dart-define` нет — экран полностью на моке, без бэкенда.
Приложение принудительно переключается в landscape (см. `main.dart`) — макет альбомный
(iPhone 15, 2320×1080).

**Переключение сценариев** (3 обязательных состояния + 5 дополнительных из макета: «нет наград»,
«БП завершён», «конец наград» с премиумом и без) — колба 🧪 в правом нижнем углу экрана. Это dev-контрол, не часть макета, но именно
он и есть «способ переключать состояния экрана», о котором просит ТЗ. Чтобы кнопку не пропустили
при первом взгляде на экран, при каждом запуске приложения поверх всего один раз показывается
затемнение с подсказкой-стрелкой на неё — снимается тапом в любом месте.

## Что реализовано

- **Главный экран БП** — все 3 обязательных состояния и 5 дополнительных состояний из макета
  («нет наград», «БП завершён», «конец наград» с премиумом и без) + переключение между ними.
- **Реальные ассеты из Figma** — фон-арка, персонаж/сцена левой панели, премиум-баннер (2
  варианта), центральный предмет (жилет / кинематографичная пара / машина) экспортированы через
  Figma MCP и лежат в `assets/images/battle_pass/`. Цвета, типографика (Geologica, шрифт
  забандлен локально), радиусы, тени, отступы — сняты из данных Figma-файла, а не на глаз.
- **Трек наград** — 100 уровней на `CustomScrollView` со слайверами фиксированной ширины
  (`SliverFixedExtentList`), поэтому позиция любого уровня и длина трека известны точно.
  Плавающее превью ближайшего юбилейного уровня (каждые 10) со стрелкой-переходом к нему,
  состояния плитки (locked/current/claimable/claimed), получение наград уровня в два тапа и
  «Забрать все награды» одной кнопкой.
- **Переход на экран «Задания»** — по нажатию на тизер-карточку; экран — минимум по ТЗ (пустой
  экран + «Назад»), см. ниже.
- **Анимации** — кросс-фейд центрального предмета и текстов при смене сценария, ripple/скейл на
  интерактивных элементах, плавные переходы состояний тайлов, анимированный прогресс-бар XP,
  а по тапу на «Дай пять!» — отдельный «живой» отклик: ладошка выпрыгивает с перехлёстом и гаснет
  под разлёт золотых искр вокруг заголовка (`AnimationController`, без сторонних пакетов).
- **Диалог с описанием предмета** — по тапу на инфо-иконку рядом с названием центрального
  предмета: превью, заголовок, текст — свой набор под «Мега пак» и свой под «Роковая женщина» /
  «Босс мафии», контент берётся из того же флейвор-объекта сценария, что и сам предмет.
- **Тема** — цвета (`MainColors`/`AppColors`) и типографика (`MobileTypo`/`AppTypography`)
  подключены как `ThemeExtension` и доступны через `context.theme.appColors` /
  `context.theme.appTypography`; letterSpacing посчитан как процент от fontSize, как в Figma.
  Размеры и отступы из макета — литералы на месте или именованные локальные константы; общая
  геометрия трека вынесена в `TrackGeometry`.

## Что осознанно упрощено / оставлено за скобками

- **Экран «Задания»** — реализован по минимуму ТЗ (пустой экран + кнопка «Назад»), но
  **архитектурный скелет полный**: `domain` (entities, repository, usecase),
  `data` (mock-datasource, repository impl, models с `fromJson`), `presentation`
  (cubit/state) — уже заведены в `lib/features/tasks/` и зарегистрированы в DI
  (`_initTasks()`), так что контент экрана достраивается без переписывания слоёв.
- **«Info bar»** — кольцо уровня/XP и таймер. Таймер отсчитывает `Season.seasonEndsAt` из
  мока; сам ивент «Дай пять!» — отдельная фича игры, его текст статичен.
- **Левая панель навигации и StatusBar устройства** — статичные изображения из макета: это
  одинаковый на всех экранах app-shell chrome, не относящийся к данным БП, поэтому не
  разбирался на интерактивные виджеты. Системный status bar (время/батарея) не дублируется —
  его рисует сама ОС.
- **Иконки наград в треке** — не уникальны на каждый из 100 уровней (в макете это тоже
  моковый/иллюстративный контент). Вместо экспорта 40 картинок — иконка + оттенок по редкости
  награды (`RewardRarity`), что и требовалось моком.
- **Тизер-карточка «Задания» и премиум-баннер** — фоновая иллюстрация экспортирована из Figma
  как картинка, заголовок/описание/кнопка — живые виджеты поверх (так их можно нормально
  анимировать/тестировать, в отличие от плоского скриншота).
- **Локализация** — строки собраны в `AppStrings`, без `intl`/ARB: приложение одноязычное,
  перевод на l10n — механическая замена этого класса.
- **Кнопка закрытия (✕)** в углу экрана — в макете это модалка поверх домашнего экрана игры; в
  этом задании БП — корневой экран, поэтому кнопка оставлена для визуального соответствия, но не
  из чего «закрываться».

## Модель данных

Схема продумана до вёрстки, proto-подобный набросок:

```proto
rpc BattlePass {
  enum RewardRarity { COMMON = 0; RARE = 1; EPIC = 2; LEGENDARY = 3; }

  message Reward {
    int32 id "id награды";
    lstring name = 64 "Название награды";
    lstring iconAsset = 128 "Путь до иконки/изображения награды";
    int32 amount "Количество (стаков)";
    RewardRarity rarity "Редкость награды";
    bool claimed "Уже получена игроком";
  }

  enum LevelState { LOCKED = 0; CURRENT = 1; CLAIMABLE = 2; CLAIMED = 3; }

  message Level {
    int32 number "Номер уровня БП";
    int32 requiredXp "XP, необходимый для достижения уровня";
    Reward freeReward "Награда бесплатной ветки (может отсутствовать)";
    Reward premiumReward "Награда премиум-ветки (может отсутствовать)";
    LevelState state "Состояние уровня относительно прогресса игрока";
  }

  outgoing Season {
    int32 seasonId "id текущего сезона БП";
    lstring seasonName = 64 "Название сезона";
    bool premiumOwned "Куплен ли премиум-пропуск";
    int32 currentLevel "Текущий уровень игрока";
    int32 currentXp "Текущий опыт внутри уровня";
    int32 maxLevel "Максимальный уровень сезона";
    repeated Level levels max 200 "Все уровни сезона по порядку";
    int64 seasonEndsAtMs "Таймстамп окончания сезона, UTC ms";
  }
}

rpc BattlePassTasks {
  message Task {
    int32 id "id задания";
    lstring title = 128 "Текст задания";
    int32 progressCurrent "Текущий прогресс выполнения";
    int32 progressTarget "Целевое значение для выполнения";
    int32 rewardXp "Награда опытом за выполнение";
    bool completed "Задание выполнено";
    bool claimed "Награда за задание забрана";
  }

  outgoing TasksScreen {
    bool premiumOwned "Куплен ли премиум-пропуск";
    bool premiumXpBuffActive "Активен ли бафф +XP от премиума";
    repeated Task tasks max 50 "Список заданий";
  }
}
```

`Level.state` вместе с `Season.premiumOwned` / `currentLevel` / `maxLevel` — это и есть машина
состояний, из которой выводятся все сценарии экрана (обязательные и бонусные).

Реализация в коде: `lib/features/battle_pass/domain/entities/` — Dart-эквивалент этой схемы
(`Season`, `Level`, `Reward`), а `lib/features/battle_pass/data/models/` — слой `Model.fromJson`,
который разбирает мок «серверных» Map'ов из `data/mock/battle_pass_mock_api.dart` — то есть
подключение реального бэкенда в будущем не потребует менять domain/presentation слои.

## Архитектура

Лёгкая Clean Architecture на фичу (`lib/features/battle_pass/`, `lib/features/tasks/`):

```
domain/       entities, abstract repository, usecases
data/         mock-datasource, models (Entity → Model, fromJson/toJson), repository impl
presentation/ cubit (state), screens, widgets
```

- **State management** — `flutter_bloc` Cubit (по ТЗ), не полноценный BLoC. Действия над
  сезоном выполняются в кубите по очереди; ошибка действия не заменяет экран, а показывается
  разово (SnackBar).
- **Бизнес-правила** — в доменной сущности: `BattlePassSeason.claimLevel` / `claimAll`
  (премиальная награда забирается только при купленном премиуме).
- **Сценарии мока** — `DemoScenarioStore` в `lib/core/demo/`: текущий сценарий «сервера», который
  читают моки. Domain о сценариях не знает — `getSeason()` / `getTasks()` без параметров.
  Отличия UI между сценариями собраны в одном месте — `ScenarioLayout.of(scenario)`.
- **DI** — `get_it`, единый контейнер `lib/core/di/injection_container.dart`, секции
  `_initBattlePass()` / `_initTasks()`. Тема в DI не участвует.
- **Навигация** — обычный `Navigator.push` через `lib/core/navigation/app_router.dart` (ручной,
  без кодогенераторов — ТЗ их прямо запрещает).
- **Result/BaseRepository** — `sealed Result<T>` с `fold` + `BaseRepository.execute()`:
  техническая причина ошибки уходит в лог, пользователю — только понятный текст.
- Экран верстается на фиксированном холсте 2320×1080 (`DesignCanvas`), совпадающем с холстом
  Figma-фрейма, и вписывается в экран с сохранением пропорций (`FittedBox`, `BoxFit.contain`) —
  на экране другой формы по краям остаются поля, но ничего не растягивается.
- **Производительность трека** — состояние, зависящее от скролла (стрелки, превью), живёт в
  `ValueNotifier`: при скролле перестраиваются только они, лента — нет. Полученные плитки
  притушены через цвета и `Image.opacity`, а не слоем `Opacity`; пунктир — `CustomPainter`.

## Тесты

`flutter test` — unit-тесты правил получения наград (`season_test`), разбора всех сценариев мока
(`battle_pass_repository_test`), кубита на `bloc_test` (включая очередь действий и ошибку
получения), `ScenarioLayout`, и widget-тесты трека (начальная позиция в каждом типе сценария,
переход к юбилейному уровню).

## Использование ИИ

Всё задание от первой строчки кода до финальной полировки выполнено в паре с Claude Code
(Claude Sonnet 5, agentic-режим в CLI). Работа шла в два неравных по времени, но одинаково
«живых» этапа.

**1. Первичная сборка экрана.**

- **Figma → данные**: доступ к макету через Figma Dev Mode MCP-сервер — снятие точных фреймов,
  стилей текста, цветов/градиентов/теней, layout-координат и экспорт финальных изображений
  (фон, персонажи, баннеры) напрямую в `assets/`.
- **Планирование**: перед кодом — явный план (архитектура, схема данных, декомпозиция
  виджетов), согласованный в диалоге, в т.ч. вопрос про степень готовности экрана «Задания».
  Раздел «Что осознанно упрощено» выше — прямое следствие этого плана.
- **Реализация**: весь код (entities/repository/usecase/cubit/widgets), конфиг pubspec,
  загрузка и локальный бандлинг шрифта Geologica — написаны и отлажены ассистентом.
- **Верификация**: `flutter analyze` после каждого крупного изменения; экран прогонялся на
  Android-эмуляторе (landscape), скриншоты по всем 3 обязательным состояниям сверялись бок-о-бок
  с соответствующими фреймами в Figma; интерактивные сценарии (клейм награды, клейм всех наград,
  переключение сценария, переход на «Задания» и назад) проверялись через `adb input tap` по
  живому запущенному приложению.

**2. Доводка: архитектура значений, тема, интерактивность.**

Существенно бо́льшая по объёму часть работы — уже после того, как экран визуально совпадал с
макетом. Здесь сознательно сменился и сам режим совместной работы: ассистент только редактирует
код и гоняет `dart format` / `flutter analyze`, а живой прогон на эмуляторе/устройстве и
визуальную сверку с макетом делает пользователь сам — обратная связь шла скриншотами,
стектрейсами реальных ошибок (например `RenderFlex overflowed`) и словесным описанием багов
(«при первом тапе подсказка не закрывается»), а не через `adb`/эмулятор со стороны ассистента.

- **Единая система темы**: цветовая палитра и типографика переведены с точечного статического
  класса (`AppColors` со `static const Color`) на `ThemeExtension`-based систему
  (`MainColors`/`AppColors`, `MobileTypo`/`AppTypography`), доступную через
  `context.theme.appColors` / `context.theme.appTypography`, — под это заведены токены на все
  реально встречавшиеся в проекте цвета и текстовые стили (включая композитные `LinearGradient`,
  которые в новой системе собираются из отдельных именованных цветов-стопов на месте), а старый
  класс `AppColors` полностью выпилен из кода после того, как не осталось ни одной ссылки на
  него. В процессе миграции нашёлся и правился реальный визуальный баг: `letterSpacing` в
  типографических токенах был взят как абсолютное число вместо процента от `fontSize` (как задаёт
  Figma) — из-за этого текст «Доступно с прокачкой!» переносился на вторую строку.
- **Дополнительная интерактивность** (сверх требований ТЗ, по итогам обсуждения «чем оживить
  экран»): диалог с описанием предмета по тапу на инфо-иконку (свой контент под каждый предмет),
  анимированный отклик на тап по «Дай пять!» (ладошка + разлёт искр), onboarding-подсказка на
  dev-переключатель сценариев при старте приложения — всё сделано на встроенных возможностях
  Flutter (`AnimationController`, `showDialog`, `Overlay`/`Stack`), без сторонних анимационных
  пакетов.

**3. Доработка после ревью.**

По фидбеку компании (пересборка трека на скролле, `settleAtEnd`, `BackdropFilter`/`ShaderMask`
поверх скролла, флаги сценариев в конструкторе) трек переписан на слайверы фиксированной ширины,
вариативность сценариев собрана в `ScenarioLayout`, логика получения наград перенесена в домен,
сценарии мока убраны из domain-интерфейсов, добавлены тесты. Работа — в паре с Claude Code
(Claude Opus 5.5).
